# Model card: quantum-kernel SVC vs classical baselines

**Where:** `api/app/quantum/qml.py`, exposed as `POST /quantum/qml/compare`, UI at `/quantum/qml`.
**Status:** Educational experiment. Synthetic data only.

## Purpose

Let users train a quantum-kernel classifier and two classical baselines on identical data and
compare them honestly. The goal is to learn how quantum kernels work. It does not show that they
are better.

## Data

The data is synthetic, generated by `make_synthetic_dataset(samples, noise, seed)`.

- **Features:** `stress_level` and `sleep_quality`, each drawn uniformly from [0, 10].
- **Label:** `high_reported_craving`. It is 1 when
  `(stress − 5)(5 − sleep)/25 + 0.3·sin(stress/1.5) > 0.05`, and a fraction `noise` of labels are
  then flipped at random.

The labelling rule is **arbitrary**. It was chosen to be mildly non-linear and is not a claim about
how stress, sleep and craving actually relate.

## Method

1. A stratified 70/30 train/test split, seeded.
2. Min-max scaling to `[0, feature_scale]` (default 1.0), fitted on the training set only.
3. **Quantum:**
   - The feature map is a `zz_feature_map` with 2 qubits and `reps` repetitions.
   - The kernel is `k(x, x') = |⟨φ(x)|φ(x')⟩|²`, computed exactly with `FidelityStatevectorKernel`, a noise-free statevector simulation.
   - The classifier is `SVC(kernel="precomputed")`.
4. **Classical:** an RBF-kernel SVC (`gamma="scale"`) and logistic regression.
5. Accuracy and F1 are reported on the test split, together with wall-clock train and predict time.

## Parameters

| Parameter | Range | Default | Effect |
|---|---|---|---|
| `samples` | 20–200 | 80 | Dataset size |
| `noise` | 0–0.5 | 0.1 | Label-flip probability |
| `feature_map_reps` | 1–3 | 2 | Depth of the feature map |
| `feature_scale` | 0.1–π | 1.0 | Kernel bandwidth (see below) |
| `seed` | ≥ 0 | 7 | Dataset and split |

**Bandwidth matters.** At `feature_scale = π` the Gram matrix is close to the identity: the model
memorises the training set and generalises poorly. Accuracy at the default seed was 0.42. At 1.0 it
reached 0.67–0.88 across the seeds we tried. At 0.25 every point looks similar and accuracy drops
again. This is a known property of quantum kernels, not a bug. It is exposed as a parameter so
users can see it for themselves.

## Limitations

- **Two features, two qubits.** At this scale a classical computer simulates the quantum kernel
  exactly, so the kernel offers no computational advantage.
- **No hardware noise.** The kernel uses exact statevector simulation.
- **Not comparable timings.** Train and predict time for the quantum model is the cost of
  *classically simulating* it. That says nothing about how it would run on quantum hardware.
- **Too little data for strong conclusions.** Test sets are small, so accuracy varies a lot with
  the seed. Compare several seeds before drawing any conclusion.
